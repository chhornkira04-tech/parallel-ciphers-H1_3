# Инструкции для работы с проектом

Эти требования распространяются на весь репозиторий, включая создание новых решателей и изменение существующих.

## Обязательная защита решателей

При создании любого решателя заранее предусмотреть переполнение, некорректный ввод, потерю точности и чрезмерное потребление ресурсов. Считать проверку этих случаев частью реализации, а не необязательной доработкой.

1. **Целочисленная арифметика.** Проверять диапазоны входных чисел, промежуточных результатов и преобразований типов. Учитывать сложение, вычитание, умножение, унарный минус, деление минимального значения на −1, размеры массивов и вычисление индексов. Если результат может превышать диапазон типа, использовать подходящий более широкий тип или `BigInteger`; расширять тип до операции, а не после нее. Для сдвигов и битовых операций отдельно проверять допустимость аргументов: `checked` не обеспечивает их математическую корректность.
2. **Проверяемая сборка.** Сохранять `CheckForOverflowUnderflow=true` и проверку этой настройки в `Directory.Build.targets`. Не добавлять `unchecked`, не отключать защиту и не ослаблять соответствующие тесты ради прохождения сборки. Если условие задачи требует циклической арифметики, сначала явно согласовать изменение этого правила и закрепить семантику тестами.
3. **Числа с плавающей точкой.** `double` и `float` не выбрасывают исключение при переполнении. Проверять конечность входных, промежуточных и выходных значений через `IsFinite`. Учитывать деление на ноль, недопустимую область функции, потерю точности, исчезновение малых значений и численную неустойчивость. Обосновывать допуски и по возможности проверять результат подстановкой или независимым условием. Не возвращать «корней нет» или другой содержательный ответ, если вычисление завершилось неудачно.
4. **Входные данные.** Проверять `null`, пустые строки, формат, диапазоны, размеры и структуру данных до вычислений и выделения памяти. Исключить выход за границы и отрицательные размеры. Явно выбирать культуру разбора и форматирования чисел. Для текстовых задач учитывать различие между UTF-16 символами и пользовательскими символами, если это важно по условию.
5. **Ресурсы.** Устанавливать обоснованные ограничения длины ввода, глубины рекурсии, степени, размеров коллекций и числа итераций. `BigInteger` устраняет переполнение диапазона, но не ограничивает время и память. Не полагаться на перехват `StackOverflowException` или `OutOfMemoryException`. Тайм-аут ожидания задачи не останавливает вычисление; для принудительного прекращения нужен отдельный процесс либо корректная кооперативная отмена.
6. **Общий путь вызова.** Реализовывать `ITaskSolver`; для обычного C#-решателя использовать `TaskSolver`. Вызывать решатели через `SolverRegistry.TrySolve` или `Solver.TrySolve`, чтобы сохранить общую защиту и для будущих реализаций. Не добавлять прямой путь вызова с автоматической отправкой ответа в обход реестра.
7. **Отказ вместо неверного ответа.** При переполнении, неподдерживаемом вводе или невозможности проверить результат возвращать отказ (`false`, ответ `null`) либо ожидаемое исключение, которое обрабатывает общая защита. Не подставлять 0, 42, пустую строку или приблизительное значение без обоснования. Не отправлять ответ автоматически после отказа. Не скрывать ошибки программирования безусловным `catch (Exception)`.
8. **Внешний код.** Проверяемый контекст вызывающего кода не включает проверки внутри уже скомпилированных библиотек. При использовании библиотек или внешних процессов отдельно проверять их числовую семантику, ошибки, лимиты и результаты. Общая проверка строки ответа не обнаруживает все ошибки промежуточных вычислений.

## Обязательные проверки перед завершением

Для каждого нового решателя добавить содержательные тесты:

- обычные примеры и границы допустимых значений;
- переполнение промежуточной операции, даже если итоговое математическое значение помещается в тип;
- деление на ноль, некорректные преобразования и другие применимые ошибки арифметики;
- `NaN`, бесконечность и точность результата, если используется плавающая точка;
- пустой, поврежденный и чрезмерно сложный ввод;
- отказ через реестр без выдачи ответа при ошибке.

Выбирать случаи по алгоритму: не добавлять бессмысленные проверки неприменимых ошибок. Сохранять общие тесты защиты будущих решателей и запрета `unchecked`. При изменении обработки отправки ответа проверять, что отказ решателя не приводит к автоматической отправке.

Запускать:

```sh
dotnet test Tests/Tests.csproj --configuration Release
```

Если проверка не прошла, исправить причину либо явно сообщить о блокирующей проблеме. Не заявлять, что решатель безопасен для всех входов только на основании успешного прохождения тестов.
